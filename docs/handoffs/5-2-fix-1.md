## Context

The architect reviewed `feat/5-2-decision-builder` and drove it in headless Chrome.

**Bug 1, reproduced.** After creating a decision:
- the URL becomes `/decisions/<id>/edit`
- but the Save button stays **disabled with "Đang lưu…" forever**, and the status line keeps saying "Đang lưu…"
- the title keeps its untrimmed input (`"  Test 573  "`)

Measured with `/decisions/new` → fill in → Lưu → edit the title → Lưu.

The cause: `DecisionBuilderPage` renders `<DecisionForm>` without a `key`, in the same position for `/new` and `/:id/edit`. React therefore **reuses the same form instance**, with `status === 'saving'` and the old draft. The new `initial` and `initialStatus` props are ignored, because they only seed `useState`. The 5-2 handoff asked for `key="new"` / `key={id}`.

**Bug 2, by reading the code.** The router state record is never refreshed after an update. The sequence:
1. create
2. edit and save (PUT)
3. reload

After the reload, `location.state.record` still holds the record from the **create**, so the form shows outdated content.

**Bug 3, reproduced.** After the first failed attempt, the status line stays "Kiểm tra lại các ô được đánh dấu." even once every field error is fixed. `'validationError'` is a stored status that only Save/"Mở case" overwrite.

**Bug 4, layout, seen in a screenshot at 390 px.** `.picker { display: contents }` puts the emoji panel into the `optionMain` grid **between** the trigger and the label input. While the panel is open:
- the trigger sits alone on the first line
- the panel comes next
- the label input and the × button are pushed below the panel

Also, the prod bundle is fine. The architect built both branches with `NODE_ENV=production`: main JS went from 96.47 to **100.70 kB gz** (+4.2 kB). The 164 kB in the 5-2 report was a dev build. `vite build` inside the dev container must run with `NODE_ENV=production` (see the 1a-2 notes in `docs/IMPLEMENTATION_PLAN.md`).

## Requirements

### F1 — Fresh form after create; fresh state after every save
- `DecisionBuilderPage` renders the form with `key="new"` on `/decisions/new` and `key={id}` on `/decisions/:id/edit`.
- After **every** successful save, create or update, call:
  ```ts
  navigate(`/decisions/${record.decision.id}/edit`, { replace: true, state: { record } })
  ```
  - **After a create:** the key changes from `new` to the id, so the form remounts from the record, with the status "saved", the normalized values, and Save enabled.
  - **After an update:** the key is unchanged, so the form does not remount. Keep setting the draft from the returned record and the status to "saved", as today. The router state now holds the latest record, so a reload shows it.
- Keep the URL search when navigating. For an update, the `view` param is never set at save time, so `location.search` can simply be preserved.

### F2 — Derived "form invalid" message
- Remove `'validationError'` from `SaveStatus`.
- The status line shows, in this order of precedence:
  1. `saving` → `t('saving')`
  2. `limitError` / `saveError` → their messages, `role="alert"`
  3. `submitted && !parsed.success` → `t('formInvalid')`, `role="alert"`
  4. `saved` → `t('saved')`
  5. otherwise empty
- The message disappears as soon as the draft becomes valid. Focusing the first invalid input on a failed attempt stays as it is.
- Any edit still clears `saved`. It also clears `limitError`/`saveError`, so a stale save error does not linger after the user changes something.

### F3 — Emoji panel below the label line
- Line 1 of the row (trigger, label input, ×) stays intact whether the panel is open or closed.
- The open panel renders as its own block **below line 1** and above the priority line, spanning the card width.
- Remove `display: contents`.
- Split the trigger and the panel so that `OptionRow` places them. For example:
  - `EmojiPicker` becomes the panel only, with its props `emoji`, `onChange`, `onClose`, `labelledBy` or `label`
  - the trigger button lives in `OptionRow`, with a ref used to return focus
  
  Any equivalent structure is fine if focus return and `Escape` keep working.

### F4 — One source for draft helpers (`draft.ts`)
Move these into `features/builder/draft.ts` and import them everywhere:
- `emptyOption()`
- `emptyDraft()`
- `draftOf(record)`
- `optionInputId(optionId)`

Delete:
- the copies in `DecisionBuilderPage.tsx` and `DecisionForm.tsx`
- the hard-coded `` `decision-option-${option.id}` `` in `OptionRow.tsx`

### F5 — Simplifications
- `formErrors.ts`: import `t` and use it directly. Drop the `messages` parameter and `errorMessages()`.
- `DecisionBuilderPage.tsx`: render `<title>` once, above the branches, not in each of the five returns.
- `OptionRow.tsx`: use its own `OptionRow.module.css`, holding the row classes moved out of `DecisionForm.module.css`. Leave only form-level classes in `DecisionForm.module.css`.
