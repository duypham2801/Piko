## Context

5-4 (branch `feat/5-4-reuse-options`, `91ad413`) added the preset "Tùy chỉnh" and the builder panel "Thêm từ có sẵn". The panel currently expands inline below the option buttons.

**Owner decision (visual review):** "Thêm từ có sẵn" must open as a **floating modal** instead of expanding the form.
- The list can be long: 4 presets plus up to 100 saved decisions.
- Inline, it pushes the form down and competes with the sticky action bar.
- The architect agrees. The choice is recorded in D-029.

The review also found a small bug:
- After a create, `DecisionForm` navigates to `/decisions/${id}${location.search}`.
- On `/decisions/new?from=food` the saved decision's preview therefore keeps a meaningless `?from=food`.

## Scope

- F1: do not carry the builder's search params to the preview after a create.
- F2: small simplifications in the 5-4 code.

## Requirements

### M1 — Native `<dialog>` modal
- **Open and close:**
  - Render a `<dialog>` while open. On mount, call `dialogRef.current.showModal()` in an effect.
  - Native `showModal()` provides the focus trap, `Escape`, the top layer and inert content behind.
  - Do not add your own focus-trap code or `Escape` key handler. Listen for the dialog's `close` event (and `cancel` if needed) and call `onClose`.
  - Closing via `Escape`, the "Xong" button, or a click on the **backdrop** returns focus to the toggle button.
  - For the backdrop click: a click whose target is the `<dialog>` element itself, outside its content box. Wrap the content in an inner element so that clicks inside never count.
- **Semantics:**
  - `aria-labelledby` points at the dialog heading, which is `<h2>` `t('addFromExisting')`.
  - Inside the dialog, the sections use `<h3>` (`t('yourDecisions')`, `t('quickPicks')`).
  - The toggle button gets `aria-haspopup="dialog"`, and no longer has `aria-expanded`/`aria-controls`.
- **Layout:**
  - Use the dialog padding, border and radius tokens of the design system: a chunky border and `--shadow-chunky`.
  - **Header:** the heading plus an outline `Button` `t('done')`. It stays visible while the body scrolls; use a sticky header inside the scroll container, or a header + `overflow-y: auto` body.
  - **Phones (default):**
    - a bottom sheet: full width, anchored to the bottom
    - top corners `--radius-lg`, bottom corners square
    - `max-height: 85dvh`
    - bottom padding includes `env(safe-area-inset-bottom)`
  - **`min-width: 48rem`:**
    - centred
    - `width: min(100% - 2 * var(--space-6), var(--content-max-width))`
    - `max-height: 80dvh`
    - all corners `--radius-lg`
  - The body scrolls with `overscroll-behavior: contain`.
  - **Page scroll lock** in `global.css`: `:root:has(dialog[open]) { overflow: hidden; }`.
  - `::backdrop { background: var(--color-backdrop); }`
- **Motion:**
  - The sheet enters with a keyframe animation on `transform` (from `translateY(var(--space-6))`) and `opacity`, using `--duration-normal` and `--ease-out`.
  - Under `prefers-reduced-motion: reduce`, there is no animation.
  - No exit animation is needed.
- **Interaction stays as in 5-4:**
  - Saved decisions are fetched only when the dialog opens. The decision being edited is excluded.
  - Loading and error lines; `<details>` groups; chips selected and disabled when the label is already in the draft; all disabled at 20, with the hint.
  - Focus stays on a chip after adding, so the user can add several in a row.
- **Exclusivity with the emoji panel:** opening the dialog closes any open emoji panel, as today. The modal makes the reverse case impossible, so remove the `setExistingOpen(false)` call from the emoji toggle.
- Remove the inline-panel styles that no longer apply.

### M2 — Token
- In `tokens.css`, add `--color-backdrop` next to the other semantic colors: `--palette-navy-900` at about 50 % opacity.
  - Use `color-mix(in srgb, var(--palette-navy-900) 50%, transparent)`, or an `rgb(… / 0.5)` value **only inside `tokens.css`**.
- Add it to the color list in `DesignPage.tsx`.

### F1 — Create destination
- After a successful **create**, navigate to `/decisions/${id}`, with **no** search string, using `replace` and `state: { record }`.
- The update path (`/decisions/${id}/edit${location.search}`) is unchanged.

### F2 — Simplifications
- `DecisionBuilderPage`:
  - call `findPreset` once
  - memoize the initial draft on the preset object: `useMemo(() => (preset ? draftFromPreset(preset) : emptyDraft()), [preset])`
- `draft.ts`: `draftFromPreset` and `withCopiedOption` build new options as `{ ...emptyOption(), label, emoji }`, instead of repeating the option literal.
