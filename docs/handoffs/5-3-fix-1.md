### F2 — `useDecisionRecord`
- Keep the behaviour exactly as specified in 5-3 C3, with two changes:
  - **Store errors without a closure.** Store the error state as `{ status: 'error' }` internally, and attach the single stable `retry` callback only in the returned value. Today a `retry` closure is stored and then replaced.
  - **Fetch once per `id` and per retry, not again when the router state changes.**
    - The fetch effect depends only on `id` and the retry counter. Read the state record for the error fallback through a ref.
    - Reason: the builder replaces the router state after every save, which currently triggers an extra `GET` per save.
