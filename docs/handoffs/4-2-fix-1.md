## Context

The 4-2 review (branch `feat/4-2-preset-preview`) found one visual bug and two small clean-ups.

**Bug:** in `HomePage.module.css`, the `@media (hover: hover) { .presetLink:hover { … } }` block comes **after** `.presetLink:active`. Both selectors have the same specificity, so the later rule wins.

On a desktop with a mouse, a press matches `:hover` and `:active` together. The architect measured it by forcing the pseudo-states in Chrome:

| State | Transform |
|---|---|
| hover | `translateY(-4px)` |
| active | `translateY(5px)` |
| hover + active | `translateY(-4px)` |

So on hover + active the card lifts instead of pressing down, while its shadow disappears.

## Requirements

### F1 — Press wins over hover
Move the two `:active` rules (`.presetLink:active` and `.presetLink:active .presetCard`) **below** the `@media (hover: hover)` block, so the press state wins whenever both match. Do not change the values, and do not add `!important`.

### F2 — Stable options
- In `PresetCasePage`, compute the options with `useMemo`, keyed on the preset and the formatted `off` string. Use it the same way for the case `key`.
- The hook must run before the not-found early return. Hooks cannot be called conditionally, so handle a missing preset inside the memo.
- Reason: `useCaseOpening` rebuilds its idle plan whenever `options` changes identity. `applyOff` returns a new array on every render.

### F3 — One modifier per row
- In `PresetPreviewPage`, drop the two computed class strings (`optionClasses`, `labelClasses`).
- Put a single modifier on the row instead: e.g. `data-off` on the `Card`, or one `.rowOff` class.
- Dim emoji and label from CSS: `.rowOff .optionEmoji, .rowOff .optionLabel { opacity: var(--opacity-dimmed); }`, or the equivalent for `data-off`.
- Delete the `.optionOff` rule. The switch must stay undimmed.
