## Context

5-1-fix-1 (`8c357b8`) keeps PGlite out of the api image, and the image is back to 186 MB. The approach works, but it is more complex than it needs to be.

The cause is a mistake in the fix-1 handoff: the guard was defined as "any path whose **name contains** `electric-sql`". That also matches the drizzle-orm variant directory `.pnpm/drizzle-orm@0.45.3_@electric-sql+pglite@0.5.8_postgres@3.4.9`. To get around it, the fix copies drizzle-orm into a hand-named directory (`drizzle-orm@0.45.3_postgres@3.4.9`) and rewires two symlinks. That means:
- 18 lines of filesystem surgery
- hard-coded versions, which go stale on the next drizzle upgrade

The variant directory **name** is harmless; only PGlite's files matter. The architect verified a simpler version on a throwaway build of `59d2dd1`. It deletes only the PGlite entries:
- the `@electric-sql` scope directories and symlinks
- the `.pnpm/@electric-sql+*` package directories

After that:
- no `@electric-sql`, `@electric-sql+*` or `pglite.wasm` path is left
- `import('drizzle-orm/postgres-js')` still works
- `node_modules` is 29.3 MB

## Scope
- Replace the fix-1 `RUN` step in `docker/Dockerfile` with the simpler removal plus a matching guard.

## Out of scope (do NOT do)
- Any other file.
- Any other Dockerfile change.

## Requirements
- Keep the existing comment line, and keep `pnpm --filter @piko/api deploy --prod --legacy /out/api` as is.
- Delete the drizzle copy, the `rm -f` of the symlinks and both `ln -s`.
- Then:
  1. Delete PGlite with `find /out/api/node_modules -depth \( -name '@electric-sql' -o -name '@electric-sql+*' \) -exec rm -rf {} +`.
  2. Run the guard: fail the build, printing the paths, if `find /out/api/node_modules \( -name '@electric-sql' -o -name '@electric-sql+*' -o -name 'pglite.wasm' \)` prints anything.
- Restore the blank line between this `RUN` and `FROM node:22-alpine AS api-prod`.
- No hard-coded package versions in the Dockerfile.
