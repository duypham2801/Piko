## Context

6-4 (the four implementer commits on `feat/6-4-shares-api`) added the shares API. The architect reviewed it:
- The behaviour is correct.
- `make check` passes: domain 48, api 41.
- The migration is additive.

What remains is duplication that has now reached a real reuse boundary, and a public handler that is more complex than needed.

**Duplicated code:**
- **`notFoundError()`** is defined three times: `routes/decisions.ts`, `routes/shares.ts` and `services/shares.service.ts`.
- **The id check** `z.uuid().safeParse(id)` → 404 is written twice: `parseDecisionId` and `parseShareId`. The public route repeats it inline.
- **"Read JSON or 400 `invalid_json`, then `safeParse` or 400 `invalid_body`"** is written four times:
  - `parseDraft` in `routes/decisions.ts`
  - `parseHistoryEntry` in `routes/history.ts`
  - `parseSharedCaseCreate` and `parseSharedCaseSpin` in `routes/shares.ts`

  Only the schema and the `invalid_body` message differ.

**The public read is more complex than needed:**
- `createPublicShareRoutes` catches the service's `HttpError(404)` and rebuilds the error body by hand (`publicNotFound`), only to add `Cache-Control`.
- It also has a separate `noStore` helper.

## Requirements

### S1 — `lib/http.ts`
Add a module with three helpers:
```ts
export function notFoundError(): HttpError                 // 404 not_found, 'The requested resource was not found.'
export function parseUuidParam(value: string): string      // z.uuid() check, otherwise throw notFoundError()
export async function readJsonBody<T>(
  c: Context<AppEnv>,
  schema: ZodMiniType<T>,
  invalidBodyMessage: string,
): Promise<T>                                              // invalid JSON → 400 invalid_json; failed safeParse → 400 invalid_body
```
- For the schema parameter type, use the same `zod/mini` type that the web client uses (`ZodMiniType` from `zod/mini`). Keep the existing `zod` import for the uuid check.
- **Routers:**
  - `decisions.ts`, `history.ts` and `shares.ts` use these helpers.
  - Delete `parseDraft`, `parseHistoryEntry`, `parseSharedCaseCreate`, `parseSharedCaseSpin`, `parseDecisionId`, `parseShareId` and the local `notFoundError` functions.
  - Each router passes its existing message: `'The decision is invalid.'`, `'The history entry is invalid.'`, `'The shared case is invalid.'`, `'The spin is invalid.'`.
- `history.ts` keeps its own `parseLimit`. It is query parsing, not a body.
- **Services:** `services/shares.service.ts` imports `notFoundError` from `lib/http.ts`. So does `decisions.service.ts`, if it has its own copy.

### S2 — Public read
- `getPublicShare` returns `SharedCaseData | null`: `null` when the share is unknown, revoked or expired. It no longer throws for "not found".
- **`createPublicShareRoutes`:**
  - Set the header first, with `c.header('Cache-Control', 'no-store')`, so it applies to every response the handler builds.
  - A malformed id, or `null` from the service → `c.json({ error: { code: 'not_found', message: 'The requested resource was not found.' } }, 404)`. Build that body once, typed with the domain `ApiError` data type.
  - Otherwise → `c.json(share, 200)`.
  - No `try/catch`. No `noStore` or `publicNotFound` helpers.
- Update the service tests that expected a thrown 404 from `getPublicShare`, so they expect `null`.
- The route tests stay unchanged and must still pass. They already check the 200, the 404, `no-store` on both, no `Set-Cookie`, and that no user is created.
