## Context

7-3 (`6f71ee3`, `13df3f0`, `68f2fe9` on `feat/7-3-case-overlay`) turned `CaseOpening` into a modal `<dialog>` above the preview/builder (D-033). The architect reviewed it in headless Chrome.

**What works:**
- `make check` passes (domain 48, api 41, 0 lint warnings).
- **Opening and closing:**
  - Opening keeps the preview mounted and makes no second `GET /api/decisions/<id>`.
  - A backdrop click does nothing.
  - `Esc` (also mid-spin), "×" and browser Back close the overlay.
  - After "×", Back does not reopen it. Focus returns to the page's "Mở case".
- **Deep links:** `/decisions/<id>/open` shows the preview with the overlay; `/presets/nope/open` shows "Không tìm thấy trang".
- **Builder:** the overlay opens above the form, and the draft survives closing.
- **Case behaviour:**
  - "Đi thôi" makes one `POST /api/history`.
  - Reduced motion reveals quickly.
  - The revealed case fits 360×740 with no scroll.
- Focus mode is gone. The winner panel is 86.6 / 95.8 px against a 96 px reserve.

**What is wrong:**
- **F1 (MUST):** closing the **share dialog** also closes the **case overlay** and navigates back to the preview.
  - It happens with `Esc` or "Đóng" inside "Chia sẻ".
  - React propagates the synthetic `close` event through the component tree. The nested `Sheet`'s `close` therefore reaches `CaseOpening`'s `onClose`, which calls `navigate(backTo, { replace: true })`.
  - The user loses the revealed result and cannot return to "Chia sẻ".
- **F2 (MUST):** at 360 px the "×" button overlaps a long title.
  - The header grid is `minmax(0, 1fr) auto minmax(0, 1fr)`. The `auto` title column takes the full width, so the "×" sits on top of the title text.
- **F3 (SHOULD):** from `48rem` the dialog always takes the full `max-height` (about 736 px at 1280×800). This leaves a large empty area under the actions.
  - The cause: `height: 100dvh` from the phone rule is not reset, so the `max-height` clamps it.
- **F4 (SHOULD):** initial focus lands on "×", not on "Mở case".
  - React's `autoFocus` runs at commit. The mount effect's `showModal()` then moves focus to the dialog's first focusable element.
- **F5 (SHOULD):** the "×" glyph renders at body size inside a 44 px button, so it is hard to see.
- **NICE:** the `48rem` block repeats `overflow-y: auto`.

## Requirements

### F1 — Only the overlay's own close navigates
- The dialog's `onClose` handler receives the event.
- It navigates only when `event.target === event.currentTarget`, meaning the case dialog itself closed. A close that bubbles up from the nested share `<dialog>` is ignored.
- Add a one-line comment saying why: React propagates `close` from nested dialogs.

### F2 — Header columns
- Change `.header` to `grid-template-columns: var(--tap-target-min) minmax(0, 1fr) var(--tap-target-min)`.
- The title stays in column 2, centred. The "×" stays in column 3.
- The title can never run under the button, and it stays visually centred on the dialog.

### F3 — Desktop height fits the content
In the `48rem` block, set `height: auto`. Keep `max-height` and the scroll. Remove the repeated `overflow-y: auto` there (NICE).

### F4 — Initial focus on the primary button
- Remove `autoFocus`.
- In the mount effect, right after `dialog.showModal()`, focus the primary "Mở case" button. Use a ref if `Button` forwards it (React 19 `ref` prop); otherwise query a `data-initial-focus` attribute inside the dialog.
- Opening still never focuses "×" first.

### F5 — "×" size
`.closeButton` uses `font-size: var(--text-xl)` and `line-height: 1`, so the glyph is clearly visible and centred.
