## Context

5-4-fix-1 (`eea31ef`, `8e45320`) turned "Thêm từ có sẵn" into a native `<dialog>`. The architect verified it in headless Chrome:
- a bottom sheet at 390 px (`x=0`, full width, bottom-anchored)
- a centred dialog at 1280 px (480 px wide)
- a backdrop click closes it and focuses the toggle
- no overflow

Two things remain.

1. **Added options look disabled, not selected.** In the dialog, a chip whose option is already in the draft is `selected` **and** `disabled`. The `Chip` primitive's `:disabled` rule paints it grey, so:
   - "already added" looks the same as "blocked by the 20-option limit"
   - the selected (teal) state never shows

   Screenshot: after adding "Phở" and "Bún", both chips are grey.
2. **No dedupe at the moment of the update.** The chip's `disabled` state is the only guard against adding the same label twice.
   - When three chips were clicked within one task, before React re-rendered, the draft ended up as `Phở | Bún | Phở`: the saved "Phở" and the preset "Phở" share a label.
   - Real taps are separate events, so this is unlikely. But the updater already receives the current draft, so it can guard cheaply.

## Requirements

### S1 — Selected + disabled chip
- In `Chip.module.css`, add a rule **after** `.chip:disabled` for a chip that is both selected and disabled (e.g. `.selected:disabled`). It keeps:
  - the selected border, background and text color (teal background, navy text, bold)
  - no shadow, `cursor: default`
- An unselected disabled chip stays grey, as today.
- In `/design`, next to the existing disabled chips, add `<Chip disabled selected>…</Chip>`.

### S2 — Check mark
- In the dialog's `OptionGroup`, a selected chip renders an `aria-hidden` `✓` before its emoji and label. `aria-pressed="true"` already tells assistive tech.

### S3 — Guard inside the updater
- In the dialog, the add handler must check the **current** draft inside the updater:
  ```ts
  onEditDraft((current) =>
    current.options.length >= DECISION_LIMITS.maxOptions ||
    current.options.some((o) => normalizeLabel(o.label) === normalizeLabel(option.label))
      ? current
      : withCopiedOption(current, option),
  );
  ```
  Equivalent code is fine. `withCopiedOption` stays pure and unchanged.

### S4 — Clean-ups
- `ExistingOptionsPanel.tsx`:
  - pass `onClose` straight to the dialog's `onClose`; delete the `handleClose` wrapper
  - delete `existingOptionsPanelId` and the dialog's `id` if nothing else references them (`aria-controls` is gone)
- `DecisionForm.tsx`: `closeExisting` does not need `useCallback`, because nothing depends on its identity. Make it a plain function, unless the dialog's effect depends on it; if so, report it.
