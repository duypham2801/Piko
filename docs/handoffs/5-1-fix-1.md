## Context

The 5-1 review (branch `feat/5-1-decisions-api`) found that **PGlite ships in the prod api image**, although it is only a devDependency. The architect built `api-prod` from `HEAD` and ran `find / -name '*pglite*'`:
- `node_modules/.pnpm/@electric-sql+pglite@0.5.8` is present, 25.2 MB.
- So are `node_modules/.pnpm/drizzle-orm@0.45.3_@electric-sql+pglite@0.5.8_postgres@3.4.9/node_modules/@electric-sql/pglite` and `node_modules/.pnpm/node_modules/@electric-sql/pglite`.
- The image grew from 186 MB to 211 MB.

**Cause:** PGlite is an optional **peer** of `drizzle-orm`. Because `apps/api` now has PGlite (as a devDependency), pnpm resolves `drizzle-orm` as a variant that lists PGlite as a dependency, and `pnpm deploy --prod` installs it with that variant.

The 5-1 validation only checked the top-level `node_modules/@electric-sql`, so it missed this.

## Scope

- F2 (SHOULD): one type for the health-check SQL dependency; delete the dead `Sql` type.

## Requirements

### F1 — No PGlite in the prod image
- In the `build` stage, right after `pnpm --filter @piko/api deploy --prod --legacy /out/api`, delete every `@electric-sql` entry under `/out/api/node_modules`. That covers:
  - the `.pnpm/@electric-sql+pglite@*` package directories
  - the `@electric-sql` scope directories and symlinks inside the drizzle-orm variant and inside `.pnpm/node_modules`
- Then add a **guard** that fails the image build if any path whose name contains `electric-sql` is still left under `/out/api/node_modules`.
  - Do not match `drizzle-orm/pglite`: that directory is drizzle's own driver code, and it must stay.
- Add a short Dockerfile comment explaining why: PGlite is a test-only devDependency, but it is an optional peer of drizzle-orm, so `pnpm deploy --prod` would ship it.
- Prod never imports `drizzle-orm/pglite`, so the dangling driver code is harmless. Confirm it by starting the built image's `node dist/index.js` far enough to fail only on the missing env/DB (or by `node -e "import('drizzle-orm/postgres-js')"` inside the image). Report what you ran.

### F2 — One SQL dependency type
- `routes/health.ts`: export the narrowed type once, e.g. `export type HealthSql = { unsafe: (query: string) => PromiseLike<unknown> };`, and use it in `HealthRouteDependencies`.
- `app.ts`: `AppDependencies.sql` uses that type instead of repeating the inline object type.
- `db/client.ts`: delete `export type Sql` if nothing uses it any more (check with `git grep -n "\bSql\b" -- apps/api`).

### F3 — Test trims
- `routes/decisions.test.ts`:
  - Delete the test `keeps API error payloads compatible with the domain schema`.
  - Instead, add `ApiError.parse(body)` to the existing `not_found` test (same request, so no extra coverage is lost).
- `test/decisions.fixtures.ts`: drop the `optionIds` array. Generate the id only from the index template (`00000000-0000-4000-8000-${String(index + 2).padStart(12, '0')}`), which yields the same three ids.
